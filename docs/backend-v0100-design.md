# 后端 v0.100.0 升钉设计

## 目标与范围

B5 已迁移具名实参和 record 值字段。本轮从 v0.99.0 升到只接受等号的 v0.100.0，保持业务行为与既有契约。
同步 JVM/native 编译器校验和、所有归档依赖的 tag 与 d1 摘要、S4 缓存地址及 native 包的工具链元数据。
八份 manifest 中仅有路径依赖的两份不增加虚构版本；JDBC 字节锁重新解析后核对差异。

## 验证方案

先用发布版检查原始源码，记录旧语法诊断；若有残留，就地最小修改并逐处列入交接报告。
核对发布资产、sidecar 与 API digest；用独立下载的 tag 归档计算 d1。
先证明错误 checksum 被拒绝，再运行 JVM 全测、core 零 Java 与负控、fmt 和静态锚点检查。
既有 CI 完整验证九族变异、S4/S5/S6、S11 双臂各 355 契约与原七 skip，以及 native 产物与其余验收。
golden 文件保持逐字节一致，测试仍遵循其 JSON/XML 归一化与具名字节断言口径。

## 状态

升钉已实现。发布版正式检查零诊断，旧 parser 的源码与嵌入审阅零候选，161 个变异锚点全部命中。
本机 JVM 461 测试、355 契约与原七 skip、core 零 Java 与四负控、fmt 和静态门均通过。
完整 CI 继续覆盖 native acceptance、双臂契约、变异与产物验收，最终 SHA、结果及墙钟写入本轮交接报告。

## 不做的（理由）

- 不改变业务逻辑或 golden：本轮仅验证工具链兼容性。
- 不增加兼容语法或长期迁移器：v0.100.0 已结束过渡期。
- 不部署、不访问服务器、不涉及 S13b：任务范围明确排除。
- 不修改 workflow：沿用现有完整门禁与预算。
