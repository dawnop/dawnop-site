# Paste 与私人记录方案

状态：2026-10-07 已部署 `d7ad81e`，CI 24 项检查及生产验证通过。公开列表和搜索、匿名提交已上线；仅支持 Markdown 正文和 `.md` 文件，不接收 `.txt` 或图片附件。

## 产品边界

- 公开 paste：任何人免登录创建、查看、浏览列表和搜索；后台只做管理。
- 私人记录：放在现有文件管理中，复用后台登录与七牛私有空间，不进入 paste 列表、搜索或公开 API。
- 风格：和 Drop 共用 `ToolLayout` 的顶栏、品牌、页面宽度、标题、卡片、按钮及手机断点；白色背景、全局蓝色重点。只保留操作、内容和必要状态，不放口号、重复品牌或首页链接。
- 不把“知道链接”称为私人。所有公开 paste 都能出现在公开列表中。

## 公开 paste

### 创建与查看

`/paste` 的“新建”入口打开 Markdown 编辑区：正文必填，标题可选；桌面支持正文/分栏/预览，手机用正文/预览切换，不增加格式或语言选择。编辑区与预览在固定高度内滚动，长文不推远发布操作；切换视图或窗口尺寸保留草稿。普通文字直接写，代码用 Markdown 代码围栏标注语言。无需账号、验证码、邮箱、密码或阅读 token。

任何访客均可粘贴正文，或选择/拖入 `.md` 文件导入正文。导入后仍需点击“发布”，不自动公开；默认不保存上传文件本身，不建立七牛对象，只存原始 Markdown。文件须为有效 UTF-8，前后端按实际字节检查大小，不靠扩展名或客户端声明判断。不接收 `.txt`、图片或二进制附件。

发布后跳到 `/paste/:id`，提供复制正文、复制链接、查看原文、下载，以及“复制为新条目”。统一保存原始 Markdown，页面从原文生成预览；复制/原文/下载 `.md` 始终返回用户原文。没有标题时不显示占位标题。

匿名发布的正文不原地修改；修订时复制成新条目。现阶段不建立匿名身份，也不发编辑/删除 token；管理端负责删除。如果以后确实需要发布者自己撤回，再单独设计删除凭据。

### 列表与搜索

列表按创建时间倒序分页，显示标题或正文首行、两行摘要、创建时间和大小，详情才加载完整正文。搜索与标题排布统一，提供加载、空列表、无搜索结果和失败重试状态；详情将下载与复制为新条目收进操作菜单。支持标题和正文搜索；内容单独检索，不混入博客的文章搜索。到期、管理员移除的条目同时从列表、搜索、详情与原文接口消失。

无密码、仅链接可见、阅后即焚、评论、点赞、阅读统计不进入第一版，避免引入多套可见性和身份规则。

### 保存期限

为了让匿名访客也能提交而不无限占用空间，匿名内容默认保存 7 天，可选 1 天、7 天、30 天，上限 30 天；管理员可在后台改为永久保留。私人记录默认永久。阅读不续期。正文必填且按 UTF-8 字节限制为 256 KiB；不接收空白正文或二进制数据。

到期条目先在所有读接口上不可见，每小时由 `dawnop-paste-cleanup.timer` 调用同一后端的 `--cleanup-pastes` 模式移除正文；创建时也顺便清理；删除操作直接移除条目。不存在、到期或已删除的详情页返回真实 HTTP 404；数据库故障保留 5xx。

### 管理

`/admin/pastes` 提供搜索、查看原文、按创建时间/期限筛选、单条/批量删除、清理到期条目、数量与正文总大小、永久保留条目以及调节提交额度。管理动作复用已有管理员登录。第一版不提供改写别人正文或伪造发布时间的功能。

## 私人记录

现状已经核实：

- 后端 `POST /api/fm/create-file` 可在当前目录新建空文件，重名返回 409。
- 后端 `POST /api/fm/save` 可保存文本；正文在七牛私有空间，文件元数据在 SQLite。
- 前端 `FilesLabView` 已接入新建文件、文本编辑/保存与 Markdown 预览。

第一版在当前文件夹工具栏、空白处右键菜单与手机操作菜单加入“新建文件”。输入文件名，新建记录统一使用 `.md`；已有其他文件仍按普通文件管理；创建成功立即进入现有编辑器。使用正常文件操作进行重命名、移动、搜索、下载与删除。

记录编辑器增加 Markdown 正文/预览切换。保留显式保存和 Ctrl/Cmd+S；编辑状态标示未保存/保存中/已保存，离开有未保存内容时提示。仅保存成功才显示“已保存”。第一版不自动上传每次输入，不做版本历史。

私人正文的权威来源是文件，不在 paste 表重复保存。可自行建“记录”文件夹，不自动移动或分类已有文件。

以后如需要分享私人记录，增加显式“发布为 paste”：先展示将公开的正文及期限，确认后创建独立的公开副本；原文件仍私有。第一版不增加这个快捷操作。

## 保存什么

公开内容使用独立 SQLite 表 `pastes`，与文章、文件管理模型分开：

| 字段 | 用途 |
| --- | --- |
| `id` | 随机公开 ID 与分享路径，非权限凭据 |
| `title` | 可选标题 |
| `content` | 原始 UTF-8 正文 |
| `created_at` | 列表排序与管理 |
| `expires_at` | 可空，空表示永久 |
| `size_bytes` | 大小限制、统计与容量预算 |

不建公开用户表，不记录阅读者、浏览历史、访问计数、设备指纹，也不把来源 IP 存入正文表。无需编辑 token、阅读 token 或额外私人记录数据库。

### 匿名提交限制（默认值）

| 限制 | 默认值 | 超限行为 |
| --- | --- | --- |
| 单条正文 | 256 KiB（UTF-8 字节） | 413，不保存 |
| 标题 | 最多 120 个 Unicode 字符，可空 | 422，保留输入 |
| 单来源短时频率 | 5 次/UTC 分钟 | 429，告知重试时间 |
| 单来源每日额度 | 30 条且正文合计不超过 2 MiB | 429，当日不再接受 |
| 全站每日额度 | 1,000 条且正文合计不超过 10 MiB | 暂停新建，当日额度恢复后再接受 |
| 存量上限 | 20,000 条或正文总量 100 MiB | 暂停新建，通知后台清理；不自动删未到期内容 |
| 保存期限 | 默认 7 天，匿名最长 30 天 | 在提交时约束 |

这些默认值可在后台“额度”中调整，后端同时保留硬上限；单条最多 256 KiB，单来源分钟额度最多 60。正文总量不等于 SQLite 物理文件大小，索引、页开销及备份另外监测。全站额度只限制创建，已有内容继续可读；重试/容量错误不丢输入，只有提交成功后清空编辑器。搜索独立限流并分页，不把写限流加在全站 `/api/` 上。

Nginx 分开限制公开提交和列表/搜索，每来源各 60 次/分钟作为外围上限；后端将分钟/日额度、正文容量、期限和插入放在同一即时事务里检查并提交，避免并发绕过和重启清空每日额度。后端只绑定回环地址，生产 Nginx 覆盖 `X-Real-IP` 为实际来源，不传入访客自行拼的同名头；后端不读 `X-Forwarded-For`。无来源头的直连请求共用一个限额桶，无无限额旁路；重复来源头和非 IP 字面量拒绝。IPv6 按 /64 归并，IPv4 映射地址与 IPv4 共用额度。IP 是来源额度而非人，校园/公司/运营商出口共享额度；拒绝过多时先调节额度，不默认加验证码。

公开 Markdown 不启用原始 HTML、脚本、iframe 或博客的可执行 viz。普通代码围栏只展示代码，不执行。外部图片默认不自动加载，避免读者仅打开页面就请求任意外站；不提供图片或二进制附件上传。

### 为额度保存的最少记录

新增短期计数表，只保存日期、来源 HMAC、成功提交数和正文总字节数，按 UTC 自然日计算，只保留当前和前一个 UTC 日（不超过 48 小时），额外保存当前 UTC 分钟及成功提交数，供短时额度使用。HMAC 使用现有 `SECRET_KEY` 经 `paste-source-key-v1` 域分离派生的专用子密钥，再与日期、规范化来源生成；同日稳定，跨日不可直接关联，不存原始 IP、正文副本或读取事件。该记录只服务于匿名提交额度，不用于用户画像，持有服务器密钥者仍可计算候选来源摘要，不把它宣称为不可追踪身份。

全站日计数与存量正文容量同样持久化/原子维护，不通过浏览器 Cookie 或身份 token 强制实现；重启不重置额度。管理删除/到期清理降低存量占用，但不退还来源当日已消耗的额度，避免提交后删除反复复用预算。

现有代理访问日志仍按现有运维策略管理，不宣称全站完全不留 IP。若后续真实滥用需要封禁，再独立设计后台封禁和短期事件记录；第一版不引入 CAPTCHA 或匿名账号。

私人记录复用现有 `files` 表的路径、类型、大小、创建/更新时间、对象 key；正文仍在七牛，不额外记录输入过程或读写历史。正常数据库与对象备份用于恢复，删除/到期并不承诺同时立即从所有备份中擦除。

## 实现范围

- Dawn：新增 `repo/repo_paste`、`svc/paste`、`api/api_paste`，创建正文表、短期额度表、配置表与 FTS5 trigram 搜索索引；至少三个字符的搜索先用索引筛选，短搜索在有限存量内匹配；公开 API 与管理 API 分开。
- 公开 API：创建、分页列表/搜索、详情、原文；管理 API：列表、删除、保留期限、清理、额度设置与统计。
- 前端：Paste 列表/Markdown 编辑与预览/详情、Paste 管理页；公开导入只接受 `.md`，文件管理的新建记录同样使用 `.md`。
- 私有运维仓：创建 API 的限流；`/paste`、`/paste/:id`、`/admin/pastes` 路由边界与存在性检查，复用现有真实 404 机制。
- 契约：覆盖匿名创建/读取/搜索、UTF-8/正文/来源与全站额度边界及并发原子性/重启持久性、到期/删除不可访问、管理鉴权、无管理凭据泄漏；文件创建接线不改变已有文件路径判词。

默认值已随本版上线，可在后台调整。

2026-10-07 已从成功的 CI run `37502151438` 部署后端，前端和 Nginx 同步切换，清理定时器已启用且首次执行成功。生产验证覆盖匿名发布/读取/原文/搜索、后台保留与鉴权、到期/删除页面的真实 404、未知路径的 GET/HEAD 404，以及七牛私人 Markdown 创建/保存/读取隔离；真实手机尺寸浏览器验证 `.md` 导入、发布、渲染和搜索，公开请求不携管理员 JWT。验证记录均已清除。

后端和前端必须同批发版，并同步私有运维仓的 Nginx 路由/限流配置。首次部署还需安装 `backend-dawn/deploy/dawnop-paste-cleanup.service` 和 `.timer` 到 systemd 单元目录，执行 `systemctl daemon-reload`、`systemctl enable --now dawnop-paste-cleanup.timer`，并手工启动一次 cleanup service 验证。两个单元的数据库、环境与权限和 `dawnop-dawn.service` 对齐。定时器未安装时，到期内容仍即时 404，但正文只在新建或管理员清理时删除。

清理不会删除未到期内容，也不会退还提交额度。SQLite 的正文总量不是物理文件大小，FTS 索引、空闲页和备份需另外监测；本版不自动 VACUUM。
