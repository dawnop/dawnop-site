# Paste 与私人记录方案

状态：设计方案，尚未实现。用户已确认公开 paste 显示所有人可浏览、搜索的列表。

## 产品边界

- 公开 paste：任何人免登录创建、查看、浏览列表和搜索；后台只做管理。
- 私人记录：放在现有文件管理中，复用后台登录与七牛私有空间，不进入 paste 列表、搜索或公开 API。
- 风格：白色背景、全局蓝色重点；只保留操作、内容和必要状态，不放口号、重复品牌或首页链接。
- 不把“知道链接”称为私人。所有公开 paste 都能出现在公开列表中。

## 公开 paste

### 创建与查看

`/paste` 的“新建”入口打开编辑区：正文必填，标题可选；默认纯文本，可以选择代码语言或 Markdown。操作只保留“发布”。无需账号、验证码、邮箱、密码或阅读 token。

发布后跳到 `/paste/:id`，提供复制正文、复制链接、查看原文、下载，以及“复制为新条目”。原始正文与展示格式分开保存，复制/原文/下载始终返回用户原文。没有标题时不显示占位标题。

匿名发布的正文不原地修改；修订时复制成新条目。现阶段不建立匿名身份，也不发编辑/删除 token；管理端负责删除。如果以后确实需要发布者自己撤回，再单独设计删除凭据。

### 列表与搜索

列表按创建时间倒序分页，显示标题或正文首行、格式、创建时间，详情才加载完整正文。支持标题和正文搜索；内容单独检索，不混入博客的文章搜索。到期、管理员移除的条目同时从列表、搜索、详情与原文接口消失。

无密码、仅链接可见、阅后即焚、评论、点赞、阅读统计不进入第一版，避免引入多套可见性和身份规则。

### 保存期限

建议默认永久，提供 1 天、7 天、30 天、永久四种选择。期限只在用户创建时确定，阅读不续期。正文必填且按 UTF-8 字节限制为 256 KiB；不另加图片或附件上传。

到期条目先在所有读接口上不可见，再由定时清理移除正文；删除操作直接移除条目。不存在、到期或已删除的详情页返回真实 HTTP 404；数据库故障保留 5xx。

### 管理

`/admin/pastes` 提供搜索、查看原文、按创建时间/期限筛选、单条/批量删除、清理到期条目、数量与正文总大小。管理动作复用已有管理员登录。第一版不提供改写别人正文或伪造发布时间的功能。

## 私人记录

现状已经核实：

- 后端 `POST /api/fm/create-file` 可在当前目录新建空文件，重名返回 409。
- 后端 `POST /api/fm/save` 可保存文本；正文在七牛私有空间，文件元数据在 SQLite。
- 前端 `FilesLabView` 已有文本查看/编辑/保存；工具栏、菜单及 API 封装缺少“新建文件”的接线。

第一版在当前文件夹工具栏、空白处右键菜单与手机操作菜单加入“新建文件”。输入文件名，默认 `.md`，也支持 `.txt` 和其他文本扩展名；创建成功立即进入现有编辑器。使用正常文件操作进行重命名、移动、搜索、下载与删除。

Markdown 增加正文/预览切换，纯文本直接编辑。保留显式保存和 Ctrl/Cmd+S；编辑状态标示未保存/保存中/已保存，离开有未保存内容时提示。仅保存成功才显示“已保存”。第一版不自动上传每次输入，不做版本历史。

私人正文的权威来源是文件，不在 paste 表重复保存。可自行建“记录”文件夹，不自动移动或分类已有文件。

以后如需要分享私人记录，增加显式“发布为 paste”：先展示将公开的正文及期限，确认后创建独立的公开副本；原文件仍私有。第一版不增加这个快捷操作。

## 保存什么

公开内容使用独立 SQLite 表 `pastes`，与文章、文件管理模型分开：

| 字段 | 用途 |
| --- | --- |
| `id` | 随机公开 ID 与分享路径，非权限凭据 |
| `title` | 可选标题 |
| `content` | 原始 UTF-8 正文 |
| `format`、`language` | 纯文本 / 代码 / Markdown 与可选代码语言 |
| `created_at` | 列表排序与管理 |
| `expires_at` | 可空，空表示永久 |
| `size_bytes` | 大小限制、统计与容量预算 |

不建公开用户表，不记录阅读者、浏览历史、访问计数、设备指纹，也不把来源 IP 存入正文表。无需编辑 token、阅读 token 或额外私人记录数据库。

防刷先用 Nginx 按来源 IP 的短时内存计数，只限制匿名创建，不要求用户验证；建议起始 5 次/分钟。后端仍做正文大小、格式枚举和非空校验，正文按文本展示，Markdown 不启用原始 HTML 或博客的可执行 viz。给 paste 正文设置独立总容量预算，达到预算时拒绝新建并提示管理员清理，保留已有内容的读取。

若实际发生重复滥用，再增加短期事件记录：每日轮换密钥的 IP HMAC、时间、动作、结果，保留 7 天，不保存原始 IP、正文或访问明细。该方案只是按需选项，不是第一版必做；现有代理访问日志另按现有运维策略管理，不宣称全站完全不留 IP。

私人记录复用现有 `files` 表的路径、类型、大小、创建/更新时间、对象 key；正文仍在七牛，不额外记录输入过程或读写历史。正常数据库与对象备份用于恢复，删除/到期并不承诺同时立即从所有备份中擦除。
